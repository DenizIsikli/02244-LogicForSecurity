## Receipt-Freeness (Voting Protocol Property)

In the FOO voting protocol:

Published messages:

- {commit(r[π[j]], v[π[j]])}inv(pk(A)), r[π[j]]

Interpretation:

- position j corresponds to voter π[j]
- commitment opened later using r[π[j]]

Key observation:

- once commitments are opened, any voter can claim any vote as theirs
- they can construct explanations consistent with the observed messages

Example:

- voter claims vote cv = {commit(r[π[k]], v[π[k]])}inv(pk(A))
- chooses blinding value b
- claims administrator sent blind(b, cv)

Result:

- intruder cannot verify which vote was actually cast

Property:

- receipt freeness
- voters cannot prove how they voted
- protects against coercion and vote buying

Limitation:

- FOO not receipt-free earlier in protocol
- before commitments open, revealing r[i] proves authorship
- dishonest administrator also breaks receipt-freeness

# First-Order Logic (FOL)

Basic syntax:

Formula ::=

- Predicate(term1,...,termn)
- Formula ∧ Formula
- ¬ Formula
- ∃Variable.Formula

Derived constructs:

- ∀x φ ≡ ¬∃x ¬φ
- φ ∨ ψ ≡ ¬(¬φ ∧ ¬ψ)
- φ ⇒ ψ ≡ ¬φ ∨ ψ

Example rule:

- ∀k ∀m : i({|m|}k) ∧ i(k) ⇒ i(m)

Meaning:

- if intruder knows encrypted message and key
- intruder can derive plaintext

---

## Semantics of FOL

Interpretation I contains:

Domain:

- non-empty set D

Functions:

- fᴵ : Dⁿ → D

Predicates:

- pᴵ ⊆ Dⁿ

Variables:

- mapped to elements of domain

Evaluation:

- I |= p(t1,...,tn) if tuple in relation
- I |= φ ∧ ψ if both formulas true
- I |= ¬φ if φ not true
- I |= ∃x φ if some element satisfies φ

Entailment:

- φ |= ψ if every model of φ is also model of ψ

# Modeling Intruder Knowledge

Predicate:

- i(m) meaning intruder knows message m

Dolev–Yao rules:

Symmetric encryption:

- i(m) ∧ i(k) ⇒ i({|m|}k)

Decryption:

- i({|m|}k) ∧ i(k) ⇒ i(m)

Public-key encryption:

- i(m) ∧ i(k) ⇒ i({m}k)

Public-key decryption:

- i({m}k) ∧ i(inv(k)) ⇒ i(m)

Pairs:

- i(<m1,m2>) ⇒ i(m1)
- i(<m1,m2>) ⇒ i(m2)
- i(m1) ∧ i(m2) ⇒ i(<m1,m2>)

# Problem of Fresh Values

Security protocols rely on:

- fresh nonces
- fresh keys

But FOL cannot represent:

- time
- state progression
- freshness constraints

Example impossible statements:

- “nonce generated once”
- “value used only in current session”

Therefore protocol modeling requires abstraction.

---

# Abstract Interpretation

Idea:

- replace infinite concrete values with finite abstract classes

Example:

Concrete nonces generated by A:

- many values

Abstract representation:

- na(A,B)
- na(A,C)
- na(A,i)

Each represents numbers used by A with a specific partner.

Protocol analysis then uses these equivalence classes. fileciteturn8file0

---

## Properties of Abstract Models

Concrete model:

- represents real executions

Abstract model:

- represents groups of executions

Relationship:

- every concrete state has abstract counterpart
- some abstract states are impossible concretely

Thus abstraction is an over-approximation.

Consequences:

- if abstract model secure → concrete model secure
- abstract attacks may be false positives

# Example: Needham–Schroeder–Lowe without Freshness

Replace fresh nonces with abstract secrets.

NA → na(A,B)

NB → nb(B,A)

Messages:

A → B:

- {f1(na(A,B), A)}pk(B)

B → A:

- {f2(na(A,B), nb(B,A), B)}pk(A)

A → B:

- {f3(nb(B,A))}pk(B)

Initial knowledge:

- na(A,B) only known to A
- nb(B,A) only known to B

Goal:

- intruder must not learn these values.

# Honest Agents in FOL

Agent sets:

Hon:

- honest agents

Dis:

- dishonest agents

Agent:

- Hon ∪ Dis

Intruder knowledge assumptions:

∀A ∈ Agent:

- i(A)
- i(pk(A))

∀A ∈ Dis:

- i(inv(pk(A)))

Intruder knows:

- identities
- public keys
- private keys of dishonest agents.

---

# Modeling Honest Protocol Roles

Example role A rule:

i({f1(na(A,B),A)}pk(B))

Response rule:

i({f2(na(A,B),NB,B)}pk(A)) ⇒ i({f3(NB)}pk(B))

Meaning:

- if intruder sends valid message
- honest agent produces protocol response

Thus agents behave like oracles for the intruder.

---

# Secrecy Goal

Security property:

intruder must not learn secrets.

Formal goal:

∀A,B ∈ Hon:

- i(na(A,B)) ⇒ attack

∀A,B ∈ Hon:

- i(nb(B,A)) ⇒ attack

Predicate attack denotes protocol failure.

Verification goal:

- prove attack cannot be derived.

---

# Resolution-Based Analysis

Resolution rule:

A ⇒ p

p ∧ B ⇒ q

-------------------

A ∧ B ⇒ q

Analysis approach:

- start from attack
- perform backward reasoning
- derive necessary conditions

Search form:

p1 ∧ p2 ∧ ... ∧ pk ⇒ attack

If all pi derivable → attack exists.

If none possible → protocol secure.

---

# Intruder Deduction Compilation

Dolev–Yao reasoning compiled into protocol rules.

Example:

if B dishonest:

i({f1(na(A,B),A)}pk(B))

intruder decrypts message using B’s private key

thus:

i(na(A,B))

This simplifies verification.

# Searching for Attack Traces

Attack possible if intruder learns:

- na(A,B)
- nb(B,A)

During resolution search:

- unify rules generating these values
- analyze cases with dishonest agents

If no derivation possible:

- protocol secure.

# Abstract Interpretation Summary

Abstract interpretation:

- maps infinite data into finite equivalence classes

Advantages:

- manageable verification
- avoids infinite state exploration

Tradeoff:

- abstract model may contain impossible states

But security guarantee holds:

- if abstract model safe → concrete model safe.

# Logos Terminal Case Study

Real industrial protocol.

Context:

- card terminals produced in large batches
- stored up to 10 years
- server certificates expire after 2 years

Goal:

- securely reconnect device after long storage.

Architecture:

Bootstrap protocol:

- executed during manufacturing
- establishes bootstrap key pair
- server stores public key

Endpoint certificate protocol:

- executed when device leaves storage
- authenticates with bootstrap key
- retrieves new certificates

# Verification Challenges

Systems involve:

Protocol composition:

Infinite state space:

- many devices

Stateful behavior:

- keys revoked
- certificates expire

Solutions:

- compositional reasoning

# Stateful Abstraction

Basic abstraction removes state information.

Problem:

- real protocols depend on evolving state

Solution:

- include limited state information in abstraction

Approach:

- set-based abstraction

Agents maintain sets of values:

- valid keys
- revoked keys

Values represented by membership patterns.

---

# Set-Based Abstraction

Example:

Alice has key ring with keys belonging to sets:

- stored
- valid
- revoked

Abstract value example:

⟨0,1,0⟩

Meaning:

- member of second set only. fileciteturn8file0

# Modeling State Changes

State change represented by term implication rule:

s →→ t

Meaning:

every property of s also holds for t.

Formally:

C[s] → C[t]

for any context C.

Example:

⟨0,1,0⟩ →→ ⟨0,0,1⟩

Models key moving from valid to revoked set.

# Attack in Logos Protocol

Detected during verification.

Attack steps:

1 intruder accesses device during storage
2 intruder runs endpoint certificate protocol
3 intruder records exchanged messages
4 later replays messages to device

Result:

- device accepts outdated certificates
- certificate authentication violated

---

# Fix for Logos Protocol

Add freshness guarantee.

Solution:

- device generates fresh random nonce
- server includes nonce in certificate response

Effect:

- replayed messages rejected

Protocol verified secure after fix.

# Key Takeaways

Abstract interpretation:

- powerful for automated verification

Advantages:

- avoids state explosion
- avoids halting problem

Limitation:

Improvement:

- stateful abstraction includes minimal state information

Applications:

- real-world industrial protocol verification
- tools like ProVerif and PSPSP
