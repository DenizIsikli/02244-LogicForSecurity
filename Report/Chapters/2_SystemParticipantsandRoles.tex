\section{System Design and Security Goals}

\subsection{System Model}

\textbf{Participants}: Hosting server (trusted), data owners (users), authorized users (friends), and untrusted programs.

\textbf{Data labels}: Each object carries a confidentiality label:
\begin{itemize}
    \item \texttt{private}: Type High (owner only)
    \item \texttt{friends}: Type Medium (owner + designated friends)  
    \item \texttt{public}: Type Low (all authenticated users)
\end{itemize}

\subsection{Security Goals}

\textbf{Confidentiality}: Type system enforces High $\not\to$ Low. Even if a program is malicious, High-labeled data cannot influence outputs visible to Low-clearance users. This prevents both explicit leaks (direct assignments) and implicit leaks (information released through control flow).

\textbf{Integrity}: Dual property: Low (untrusted) data cannot modify High (trusted) storage. In practice, write authorization is checked via integrity labels and enforced through type constraints.
