\section{Server API and Security Semantics}

Each API command is specified as a typed transition with explicit checks. The API assumes authenticated TLS sessions as stated in the project description.

\subsection{Data Types}

We use:
\begin{itemize}
    \item \texttt{Principal}: actor in $\mathcal{A}$,
    \item \texttt{ConfLabel}: conjunction of policies $(o:r)$,
    \item \texttt{IntegLabel}: conjunction of policies $(o \leftarrow w)$,
    \item \texttt{Label}: pair $(C,I)$,
    \item \texttt{DataId}, \texttt{ProgramId}: server-generated identifiers.
\end{itemize}

For each command, response is either success value or \texttt{error(code,msg)}.

\subsection{Command List}

\textbf{1) UPLOAD}$(token, payload:bytes, C:ConfLabel, I:IntegLabel, meta)$
\begin{itemize}
    \item Checks: token valid; label syntax valid; actor names valid.
    \item Effect: create object with label $(C,I)$ and owner as uploader.
    \item Response: \texttt{ok(dataId)}.
\end{itemize}

\textbf{2) READ\_DATA}$(token, dataId)$
\begin{itemize}
    \item Checks: requester is allowed by confidentiality component of object label.
    \item Effect: no state change.
    \item Response: \texttt{ok(payload,label,meta)}.
\end{itemize}

\textbf{3) WRITE\_DATA}$(token, dataId, payload')$
\begin{itemize}
    \item Checks: requester allowed by integrity policy; update preserves label constraints.
    \item Effect: replace payload, preserve or tighten label.
    \item Response: \texttt{ok(version)}.
\end{itemize}

\textbf{4) UPLOAD\_PROGRAM}$(token, src, signature)$
\begin{itemize}
    \item Checks: source parses; every variable has label annotation or inferable label; checker validates flow rules under Myers-Liskov style lattice order.
    \item Effect: store typed IR and interface constraints.
    \item Response: \texttt{ok(programId, inferredInterface)} or \texttt{error(type\_error,...)}.
\end{itemize}

\textbf{5) RUN\_PROGRAM}$(token, programId, inputIds, outC:ConfLabel, outI:IntegLabel)$
\begin{enumerate}
    \item Resolve input labels from stored objects.
    \item Verify call matches program interface and pre-checked constraints.
    \item Compute required output lower bound label $L_{req}$.
    \item Accept only if $L_{req} \sqsubseteq (outC,outI)$.
    \item Execute and store output with label $(outC,outI)$.
\end{enumerate}
Response: \texttt{ok(resultDataId)} or \texttt{error(flow\_violation,...)}.

\textbf{6) DECLASSIFY\_AND\_RELEASE}$(token, dataId, transform, params, targetC)$
\begin{itemize}
    \item Checks: transform in trusted whitelist; params satisfy policy; caller has authority for each owner policy relaxed from source $C$ to $targetC$.
    \item Effect: run trusted transform, produce new object with confidentiality $targetC$ and policy-defined integrity.
    \item Response: \texttt{ok(releasedDataId)}.
\end{itemize}

\textbf{7) AUDIT\_QUERY}$(token, filter)$
\begin{itemize}
    \item Checks: requester is admin or owner-authorized auditor.
    \item Effect: no state change.
    \item Response: \texttt{ok(entries)} where entries include caller, time, source label, target label, authority proof reference, and transform id.
\end{itemize}

\subsection{Why This API Is Secure by Construction}

The interface intentionally separates concerns:
\begin{itemize}
    \item data commands enforce reader/writer policies on stored objects,
    \item program commands enforce static flow safety before execution,
    \item declassification command centralizes all confidentiality relaxation under explicit authority.
\end{itemize}
