\section{Server API Design}

The server provides five main commands, all enforcing label-based access control and non-interference properties.

\subsection{Data Management Commands}

\textbf{UPLOAD(data, principal, readers)}

Store data with decentralized label $L = \text{principal}: \text{readers}$. Returns data\_id. Only owner and authorized readers can access via READ.

\textbf{READ(data\_id, caller)}

Retrieve data if caller authorized. Check: is caller = owner or caller $\in$ readers? If yes, return data with label. If no, return error. Enforces confidentiality by access control.

\subsection{Program Execution Commands}

\textbf{ANALYZE\_WHITEBOX(program\_source, input\_ids, output\_principal)}

Upload program source code. Server type-checks against input labels:
\begin{enumerate}
\item Retrieve input labels $L_1, \ldots, L_k$ from stored data
\item Parse program; assign each variable a label
\item Check: for all assignments $x := e$, label$(e) \leq$ label$(x)$
\item Check: program counter tracking prevents implicit flows
\item If type-checking succeeds: execute program, infer output label, store
\item If failure: reject program, log error (no execution)
\end{enumerate}

Guarantee: successful analysis $\Rightarrow$ no information leaks.

\textbf{RUN\_BLACKBOX(binary\_path, input\_ids)}

Execute untrusted binary. Output labeled conservatively: $L_{\text{out}} = L_1 \sqcup L_2 \sqcup \cdots$ (join of input labels). Result: no information leaks beyond most restrictive input.

\subsection{Declassification Command}

\textbf{DECLASSIFY(data\_id, new\_readers, justification, authorizing\_principal)}

Expand reader set. Check: is authorizing\_principal the owner listed in current label? Yes $\Rightarrow$ proceed; No $\Rightarrow$ deny. Update label from $o: R$ to $o: R'$ (with $R' \supseteq R$). Log: timestamp, principal, justification, signature. Enables owner-authorized access expansion for research, de-identification, etc.
