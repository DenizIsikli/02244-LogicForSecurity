\section{Core Operations}

The server provides API commands that interact with the Volpano type system:

\subsection{Data Operations}

\textbf{UPLOAD}$(data, label)$: Store data with confidentiality label (private, friends, public). Stored objects have type High, Medium, or Low respectively.

\textbf{READ}$(data\_id, user)$: Return data if user has access. Type of returned data matches the label:
\begin{itemize}
    \item private → High: Only owner can read
    \item friends → Medium: Owner and designated friends can read
    \item public → Low: All users can read
\end{itemize}

\textbf{WRITE}$(data\_id, new\_data)$: Modify data. Authorization is checked via integrity labels. The updated data has type $\tau_{\text{old}} \sqcup \tau_{\text{new}}$.

\subsection{Program Execution}

\textbf{RUN\_PROGRAM}$(program, input\_ids, output\_label)$: Execute program with Volpano type checking.

\textbf{Process}:
\begin{enumerate}
    \item Assign types to inputs based on their labels
    \item Type-check program body (verify no High→Low flows)
    \item If type-check passes, execute program
    \item Store output with inferred type
    \item If type-check fails, reject program (no execution)
\end{enumerate}

\subsection{Declassification}

\textbf{RELABEL}$(data\_id, new\_label)$ with declassification: Owner can downgrade labels (e.g., private→public) for approved transformations:

\begin{itemize}
    \item \textbf{Anonymization}: Remove PII (names, IDs, contact info)
    \item \textbf{Aggregation}: Compute statistics (mean, median) → safe for public
    \item \textbf{Differential Privacy}: Add calibrated noise to queries
\end{itemize}

These operations are marked as trusted declassifiers and bypass normal type checking. Example: anonymize patient records → output labeled Low (safe for researchers).
